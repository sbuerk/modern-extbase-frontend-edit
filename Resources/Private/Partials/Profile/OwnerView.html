This exists because the edit plugin renders it twice and must not render it twice differently: once inside the custom element as the no-JavaScript view the component replaces, and once on its own when a workspace is active and there is no component. A copied block would drift, and the difference between the two branches is what wraps this, not what is in it. It is deliberately not Profile/Card, which pairs the image with the name for the detail view. The composition here is the owner's, and it carries the two collections Card does not. The image is passed rather than read from the profile inside, so that a caller which resolves it differently - a workspace overlay, a placeholder - changes one argument instead of this file.
