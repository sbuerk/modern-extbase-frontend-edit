Template: Profile/List - the list plugin. Variables assigned by ProfileController.listAction profiles array of entries, each shaped profile Domain\Model\Profile editable bool, display only ownership flag settings array settings.showPageUid page holding the show plugin, 0 when unconfigured settings.editPageUid page holding the edit plugin, 0 when unconfigured Both URIs are built here rather than in the partials: only a template knows which plugin it links to, and keeping that knowledge out of the partials is what lets the show plugin reuse them unchanged. A page uid of 0 means "not configured" for both settings. It is guarded rather than passed on, because f:uri.page and f:uri.action both resolve a page uid of 0 to the current page - which for the list plugin would be a link to itself. The edit link points at the configured page and carries no profile argument. The edit plugin is a later change, so an Extbase action URI into it would be an assumption about a plugin name, a controller and an argument name that nothing verifies. The argument is added together with that plugin. The list carries its own heading, so the cards below it are one level deeper - hence the h3.
